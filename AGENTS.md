# Preferred code style

Use readable, expanded, educational source files like the user's annotated F1ApiService example.

- Use two spaces, single quotes in JavaScript/TypeScript, and semicolons.
- Expand functions, objects, conditionals, markup and CSS across lines; avoid compressed source.
- Separate imports, state, setup, requests, cleanup and helpers with blank lines.
- Include JSDoc/block comments explaining classes, services, interfaces, methods and important logic. Document reactive dependencies, failure handling and cleanup accurately.
- Add concise inline comments for important steps. Preserve behavior in formatting-only tasks.
- Do not add comments to JSON or generated data.
- Apply these principles to future projects using idiomatic language formatters.
- Respect required project formatters; use these defaults in new projects.

Use npm run format and npm run format:check. Preserve the current design, photo licensing checks and free Pages hosting.
